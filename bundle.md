## Task: Create Smart Product Bundles on the Sale Page

We currently have a Sale Offers API that returns discounted products. The client now wants us to automatically create **bundles of 2 complementary products** from these sale products and display them prominently on the Sale page.

### 1. Bundle Generation

Use the existing sale-offer product data as the source.

Create **pairs of 2 products that make logical sense together**, rather than pairing products randomly.

Examples of sensible pairings from the provided data:

- Tata Tea + Jabsons Dry Kachori → tea + snack
- Tata Tea + Tata Tea flavored/variant tea → related tea products
- RTC Chicken Tikka Masala + RTC Tandoori Chicken → complementary cooking products
- RTC Butter Chicken + RTC Kadhai Chicken → related ready-to-cook products
- RTC Paneer Butter Masala + RTC Kadhai Paneer → paneer/vegetarian cooking pair
- Ginger Paste + Garlic Paste → complementary cooking ingredients
- Himalaya Neem Face Wash + Himalaya Aloe Vera Face Wash → same brand/category skincare pair
- India Gate Brown Rice + India Gate Brown Basmati Rice → related rice products
- Tata Tea Gold 450g + Tata Tea Premium 450g → comparable tea variants

Avoid nonsensical combinations such as tea + face wash or ghee + tea unless there is a strong business reason.

The bundle generation should be deterministic and maintainable. Do not simply pair products based on array position.

### 2. IMPORTANT: Use Product IDs

Each bundle must retain the actual MongoDB product `_id` values.

Do **not** use:

- array indexes
- SKU as the primary identifier
- product names
- slugs

A bundle should conceptually look like:

```ts
{
  id: "unique-bundle-id",
  productIds: [
    "6a60a89871da977f31c741cf",
    "6a27c8bb343e0d539bf4664e"
  ],
  products: [product1, product2],
  title: "...",
  description: "...",
  totalPrice: ...,
  originalPrice: ...,
  discountAmount: ...
}
```

The `productIds` must contain the exact `_id` of each product.

Use the product IDs when adding products to the cart.

### 3. Bundle Pricing

For every bundle calculate:

- Combined original price
- Combined discounted/current price
- Total savings
- Discount percentage where appropriate

For example:

```ts
originalPrice = product1.originalPrice + product2.originalPrice;
bundlePrice = product1.unitPrice + product2.unitPrice;
savings = originalPrice - bundlePrice;
```

Do not invent an additional bundle discount unless the existing business logic explicitly supports it.

Clearly communicate that the bundle consists of **2 products**.

### 4. UI Location

On:

`src/app/(dashboard)/sale/page.tsx`

there is currently sale content around:

`page.tsx#L104-114`

Add the new **Bundles / Pair & Save** section **before the existing sale products section at that location**.

The UI should feel polished and production-ready.

Suggested section:

**Pair & Save**

> Hand-picked combinations you’ll love

Each bundle card should clearly show:

- Product image for item 1
- Product image for item 2
- Product name for both products
- Original combined price
- Bundle/current combined price
- Total savings
- An attractive visual indicator such as `SAVE ¥XXX`
- `Add Bundle to Cart` button

Make the relationship between the two products visually obvious. For example:

```text
[ Product 1 ]   +   [ Product 2 ]

Tata Tea              Jabsons Kachori
900g                  160g

        Pair & Save

Original: ¥1550
Now:      ¥1395
You save: ¥155

        [ Add Bundle to Cart ]
```

Use the project's existing design system, components, spacing, typography, colors, buttons, cards, and responsive patterns rather than introducing an unrelated design language.

The UI must work well on:

- desktop
- tablet
- mobile

### 5. Add Bundle to Cart Behavior

When the user clicks **Add Bundle to Cart**, BOTH products in that bundle must be added to the cart.

For example:

```ts
addBundleToCart(bundle);
```

should effectively add:

```ts
addToCart({
  productId: bundle.products[0]._id,
  quantity: 1,
});

addToCart({
  productId: bundle.products[1]._id,
  quantity: 1,
});
```

Use the project's existing cart implementation and APIs/state management.

Do not create a new independent cart system.

If either product is already in the cart, follow the existing cart behavior for quantity updates instead of creating duplicate cart entries.

After successfully adding the bundle:

- show the existing cart success feedback/toast if available
- make it clear that **both products were added**
- update the cart count/state correctly

### 6. Error Handling — REQUIRED

Add proper error handling throughout the bundle flow.

Handle cases such as:

- Sale API fails
- Sale API returns an invalid/empty response
- A product is missing `_id`
- A bundle contains fewer than 2 valid products
- A product is inactive
- A product is out of stock
- A product has invalid/missing pricing
- Adding the first product succeeds but adding the second product fails
- Cart API/state update fails
- User clicks Add Bundle multiple times quickly

Do not silently swallow errors.

The UI should:

- disable the bundle button while the bundle is being added
- show an appropriate loading state
- prevent accidental duplicate submissions
- show a user-friendly error message when something fails
- restore the button to its usable state after failure

If adding a bundle requires multiple cart operations and the second operation fails, handle the partial-success scenario gracefully and ensure the cart state remains consistent with the existing cart implementation.

### 7. Data Validation

Before displaying a bundle, validate that both products:

```ts
product?._id;
product?.name;
product?.images?.[0];
product?.unitPrice;
product?.originalPrice;
```

are usable.

Do not render broken bundle cards.

Filter out invalid bundles safely.

### 8. Bundle Quality

The goal is not to display as many bundles as possible.

Prioritize **quality and relevance**.

Use product attributes such as:

- product name
- manufacturer
- SKU
- category/type inferred from the product
- product description
- price
- food/snack/tea/skincare/cooking relationships

to determine sensible pairings.

Avoid duplicate or near-identical bundles.

Do not pair the same product into multiple bundles unless there is a clear reason.

### 9. Maintainability

Keep bundle-generation logic separate from the JSX/UI where practical.

For example:

```ts
generateProductBundles(products);
```

and:

```ts
handleAddBundleToCart(bundle);
```

The implementation should be easy to modify later if the business wants different pairing rules.

Add clear TypeScript types for:

```ts
Product;
ProductBundle;
```

Do not use `any` unless absolutely unavoidable.

### 10. Important Constraints

- Do not break the existing sale page.
- Do not replace the existing sale products section.
- Add bundles before the existing sale products section.
- Reuse existing cart functionality.
- Reuse existing UI components where possible.
- Use actual product `_id` values for bundle/cart operations.
- Never rely on array indexes as product identifiers.
- Include robust error and loading states.
- Make the bundle UI responsive and visually polished.
- Keep the implementation production-ready rather than using hardcoded mock products.

The provided sale API response contains 36 discounted products and should be treated as the source data for designing and validating the pairing logic.
